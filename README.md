# jumpyball-decomp

Порт игры JumpyBall (Windows Mobile / Pocket PC, экран 240x320) на C89 + SDL2.

Логика восстановлена реверс-инжинирингом оригинальных `JumpyBall.exe` и `hss.dll`.
Код порта - собственный; из оригинальной поставки в репозиторий входят только
ассеты (`BITMAP`, `Sounds`, `Musics`), без бинарников и декомпилированных
исходников.

## Что реализовано

- Псевдо-3D трасса с построчной проекцией, пять тем оформления
- Физика мяча, прыжок (в том числе автопрыжок), респавн
- Уровни, разблокировка, таймер и HUD оригинальным шрифтом
- Меню: главное, выбор уровня, настройки, «о программе»
- Настройка управления: мастер переназначения шести клавиш с сохранением в
  `keys.cfg`
- Звук: WAV-эффекты и музыка `.tkm` (4-канальный ProTracker `M.K.`)
  собственным плеером в `jb_mod.c` / `jb_mod_effects.c`

## Сборка

Код - ANSI C (C89). Нужны компилятор C и SDL2.

### CMake (Windows, Linux, куда угодно)

```
cmake -S . -B build-cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build-cmake
```

SDL2 ищется тремя способами по очереди: `find_package(SDL2 CONFIG)`,
`find_package(SDL2)`, затем `pkg-config sdl2`. Если SDL2 лежит в нестандартном
месте, передайте `-DCMAKE_PREFIX_PATH=<префикс sdl2>`; для vcpkg -
`-DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake`.
`BITMAP`, `Sounds` и `Musics` копируются рядом с бинарником после сборки
(отключается `-DJUMPYBALL_COPY_ASSETS=OFF`).

На этой машине конфигурация с готовыми путями лежит в `build-cmake.cmd`.

### Проверка на строгий C89

`tools\c89check.cmd` прогоняет все `.c` через clang (тот, что идёт с Visual
Studio Build Tools) с `-std=c89 -pedantic-errors -Wall`. Компоновки нет - это
проверка того, что код не опирается на расширения MSVC и соберётся другим
компилятором, в том числе gcc/clang под Linux.

### MSVC напрямую

Пути к MSVC и SDL2 заданы в начале `build.cmd`:

```
set VCVARS=D:\VS\BuildTools\VC\Auxiliary\Build\vcvars32.bat
set SDL=D:\vcpkg\installed\x86-windows
```

Поправьте их под свою машину и запустите:

```
build.cmd
```

Результат - `build\jumpyball.exe` вместе с `SDL2.dll` и ассетами.

### Android (APK)

`tools/android_prepare.sh` собирает дерево Gradle в `build-android/`: скачивает
исходники SDL2 `release-2.32.10`, раскладывает шаблон `android-project`,
копирует в него `jb_*.c` / `jb_*.h` и ассеты в `app/src/main/assets`. Нужны JDK
17 и Android SDK с NDK (путь берётся из `ANDROID_NDK_HOME` / `ANDROID_NDK_ROOT`).

```
sh tools/android_prepare.sh
cd build-android && ./gradlew assembleDebug
```

Готовый APK - `build-android/app/build/outputs/apk/debug/app-debug.apk`,
универсальный: в одном файле лежат ABI `armeabi-v7a`, `arm64-v8a`, `x86`,
`x86_64`; minSdk 21, ориентация портретная.
Ассеты читаются прямо из APK через `SDL_RWops`, а `keys.cfg` пишется во
внутреннюю память приложения.

### Сборки в CI

`.github/workflows/build.yml` собирает и прогоняет игру на пяти конфигурациях:
Linux x86_64 и arm64 (плюс проверка на строгий C89), Windows x86 и ARM64,
Android APK. Настольные сборки проверяются выгрузкой кадра в headless-режиме -
файл обязан быть ровно 240*320*2 байта, - APK проверяется на наличие
`libmain.so` / `libSDL2.so` для всех четырёх ABI и ассетов внутри архива.

## Управление

По умолчанию: стрелки - движение, `Space` - прыжок, `Escape` - меню.
Переназначить можно в «Настройки» -> «Управление»: мастер по очереди просит
нажать клавишу для «влево», «вправо», «вверх», «вниз», «прыжок» и «меню»; уже
занятая клавиша не принимается.

На Android управление сенсорное: под кадром игры рисуется панель с крестовиной,
кнопкой прыжка и кнопкой меню, работает мультитач (например «вправо» и «прыжок»
одновременно). Размер кнопок считается от размера экрана, поэтому панель
одинаково умещается и на маленьком, и на большом устройстве. Аппаратная кнопка
«Назад» выходит из игры. Ту же панель можно посмотреть на десктопе - переменная
окружения `JUMPYBALL_TOUCH=1`.

Раскладка пишется в `keys.cfg` рядом с исполняемым файлом - шесть десятичных
кодов клавиш SDL, по одному на строку, в том же порядке. Это сознательное
отступление от оригинала: тот хранил `keys.dat` / `keys2.dat` с кодами VK в
кодировке «база 1000 + смещение 100», а коды VK не совпадают с кодами SDL, так
что переносить оригинальный формат было бы бессмысленно. Файл с непривязанной
или повторяющейся клавишей отбрасывается, и берутся значения по умолчанию.

## Чекпоинты

Чекпоинты берутся из битмапов уровней: чисто красный пиксель (RGB 255,0,0) в
`BITMAP/309.bmp`, `333.bmp`, `334.bmp` - это чекпоинт. Загрузчик карты пишет их
столбец и строку в таблицы, начиная с индекса 1, а респавн после падения
ставит мяч в последний чекпоинт, пройденный раньше текущей позиции камеры.

Второе сознательное отступление от оригинала: в оригинале обход таблицы
чекпоинтов не ограничен их количеством и завершается только записью со строкой
больше порога, поэтому в конце уровня он читает память за таблицей. Порт
ограничивает обход числом фактически найденных красных пикселей.

## Ассеты

`BITMAP`, `Sounds` и `Musics` лежат в репозитории и копируются в `build\` при
сборке. Игра ищет их рядом с исполняемым файлом; путь можно переопределить
переменной окружения `JUMPYBALL_ASSETS`.

## Аргументы командной строки

| Аргумент | Значение |
| --- | --- |
| `--level=N` | стартовать сразу в уровне N |
| `--screen=N` | стартовый экран меню |
| `--index=N` | стартовая позиция в меню |
| `--unlocked=N` | сколько уровней открыто |
| `N` (число) | масштаб окна |
| путь | выгрузить кадр (RAW 16bpp) и выйти |

## tools/

`modtest.c` - офлайн-проверка музыкального плеера: рендерит `.tkm` в WAV и
печатает peak/RMS и длительность, без звуковой карты. Сборка - `tools\modtest.cmd`,
запуск - `modtest.exe <in.tkm> <out.wav> [volume] [loop]`.

`c89check.cmd` - проверка на строгий C89 (см. раздел «Сборка»).

## Модификация уровней.

В игре есть всего три уровня в котором используются разные BITMAP. Так вот можно сами уровни редактировать используя Paint или другие редакторы. В основном уровни редактируются легко, 309.bmp, 333.bmp, 334.bmp это первый, второй, третий уровень. Их значения: черный - место где можно катать шарик, белый - вода, трава, по которому нельзя катать, красный - чекпоинт
